# Подготовка сдачи

Материалы сдаются не позднее чем за один час до защиты. Отсутствующие материалы необходимо прямо назвать.

## Обязательные материалы

- Ссылка на репозиторий команды с исходниками, промптами, catalogue, схемами и workflow.
- README с установкой, переменными окружения, командами и значениями exit code.
- Настоящие `report.json` и `report.md` проверки официального target через DeepSeek.
- Настоящий `execution.log` шага GitHub Actions или скриншот, где видны код, число находок и ID требований.
- Краткое описание подхода: `docs/APPROACH.md` (при необходимости экспортировать в 1–2 страницы).
- `metrics.json`: длительность и токены, полученные из реального запуска.
- SHA тестового проекта, совпадающий с report.json.
- Явный перечень ограничений и отсутствующих материалов.

## Перед упаковкой

1. Вставить ключ в `.env`, выполнить реальный scan и просмотреть доказательства.
2. Проверить, что все восемь статусов завершены; incomplete не выдавать за успешную проверку.
3. Опубликовать репозиторий, настроить secret и обязательный check, получить реальный CI-лог.
4. Убедиться в отсутствии ключей/паролей/токенов во всех материалах и скриншотах.
5. Собрать исходники и результаты. Не включать `.env`, `.venv`, `.git`, runtime, закрытые ключи и токены.

```powershell
.venv/Scripts/python.exe scripts/package_submission.py --run reports/run-ДАТА-ВРЕМЯ --output submission.zip
```

Упаковщик проверяет, что есть JSON/Markdown/лог/метрики и результат не incomplete. Он не подменяет экспертную проверку и не доказывает, что переданный лог получен именно из GitHub Actions. Перед сдачей прикладывайте подтверждение CI отдельно, если локальный запуск использовался для отчёта.
