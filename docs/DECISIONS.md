# Принятые решения и вопросы организаторам

1. **Ошибка API и отчёт.** ТЗ 4.3.4 требует сохранения отчёта вне зависимости от результата, но 4.7.3 отдельно предписывает аварийное завершение без отчёта при недоступности модели/лимитах. Принято более конкретное правило: при внешней ошибке нет report.json/report.md, есть error.json, инвентаризация и лог; артефакты загружаются всегда. При общем таймауте — частичный отчёт по 4.7.2. Это решение следует подтвердить у организаторов.
2. **Граница репозиториев.** Агент и workflow находятся в репозитории команды. Тестовый проект отдельным checkout остаётся неизменным. Push команды запускает анализ выбранного target ref. Для реакции непосредственно на push организаторов нужен предоставленный ими trigger/dispatch — чужой репозиторий мы не изменяем.
3. **Ошибки и неполнота.** Если хоть одно обязательное требование осталось inconclusive, проверка не пройдена с кодом 2. Ноль подтверждённых находок не означает полноту проверки. Rejected-кандидат не является доказательством безопасной реализации.
4. **Дополнительные дефекты.** Подтверждённые EXTRA-находки не блокируют проверку. Невозможность выполнить сам дополнительный анализ означает неполноту, потому что п.4.8.1 включает спецификацию в предмет проверки.
5. **Грязное дерево.** Для достоверного SHA принимается только чистый Git checkout. Неотслеживаемый файл вызывает отказ; игнорируемые рабочие данные не включаются в область исходного кода. Все файлы, предназначенные для оценки, должны быть закоммичены.
6. **Нормативная база.** Каталог отражает текст предоставленного ТЗ. Агент проверяет документальные ссылки и технические механизмы, не объявляет юридическую экспертизу или сертификацию.
7. **Провайдер.** Используется официальный DeepSeek API. Разрешённую модель, бюджет и право передачи исходников подтверждает команда у организаторов. Других провайдеров и автоматического fallback нет.
