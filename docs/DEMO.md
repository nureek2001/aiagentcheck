# Демонстрация на защите

## Что открыть

1. Репозиторий https://github.com/nureek2001/aiagentcheck и вкладку Actions.
2. Локальную панель: `scripts/dashboard.ps1 -GitHubRepo nureek2001/aiagentcheck`, затем
   http://127.0.0.1:8765. Она использует существующую авторизацию GitHub или локальный GH_TOKEN.
3. ТЗ хакатона и спецификацию Helpdesk в официальном репозитории — отдельно от исходников агента.

## Что показать

* Push в репозиторий команды запускает Security assessment. Проверяемый внешний Helpdesk закреплён
  переменной TARGET_REF. Это демонстрация интеграции; push в чужой репозиторий её не запускает.
* Agent tests проверяет агент на Windows и Linux без обращений к DeepSeek.
* Панель показывает реальные статусы Actions. Во время облачного анализа доступны статусы шагов,
  а подробные находки появляются после публикации artifact. Внутренний счётчик частей виден в живом
  режиме только для локального scan.
* По завершении откройте report.json/report.md и dashboard.html из Artifacts. Покажите SHA target,
  статусы всех восьми требований, доказательства и рекомендации.
* При коде 1 или 2 следующий job Delivery gate пропускается. Код 2 — неполный анализ, а не отсутствие
  нарушений. Внешний сервис недоступен — только диагностика, без итогового отчёта оценки.
* Откройте подтверждённую находку и предложение патча. Генерация — отдельный платный запрос, только
  после нажатия и подтверждения. Можно использовать уже сохранённое предложение без новых затрат.
* Покажите diff и рекомендуемые тесты. Не называйте предложение применённым или проверенным
  исправлением: проверены совпадение замен и синтаксис Python; тесты продукта не запускались.

## Как подключить к рабочему приложению

Шаблон `product-workflow.example.yml` помещается только в разрешённый продуктовый репозиторий.
Он закрепляет доверенную версию агента и проверяет `github.sha` вызывающего проекта. Защита ветки
должна требовать реальный security status check перед merge; deploy зависит от security job.
Настройки и исходники организаторов не изменяются.

## Чего не заявлять

* Что браузер автоматически открывается на любом компьютере после push.
* Что локальная панель уже размещена как публичный сайт.
* Что зелёные тесты агента означают безопасность Helpdesk.
* Что LLM гарантированно нашла все уязвимости или заменила ручной аудит.
* Что отчёт `incomplete` пригоден как завершённая оценка для сдачи.
* Что повторяющиеся записи разных разделов — уникальные уязвимости.

Новый push запускает новый платный анализ. Для просмотра результатов используйте готовые запуски,
а не создавайте коммиты исключительно ради повторного открытия отчёта.
